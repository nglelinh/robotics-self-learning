Thời lượng: **~150 phút** nếu thẻ nhớ và board đã có. Khoảng 40 phút nếu bạn chỉ viết phiếu cho laptop Ubuntu 24.04 và hoãn SBC.

## Mục tiêu

Bạn cài Ubuntu 24.04 headless lên Raspberry Pi 5, hoặc bạn kiểm tra Jetson Orin Nano đang ở Ubuntu nào trước khi chọn distro ROS. Bạn SSH vào board, đặt udev để ESP32 thành `/dev/esp32`, viết một unit systemd cho micro-ROS agent, và đặt cùng một `ROS_DOMAIN_ID` trên laptop và trên robot. Bạn giải thích vì sao Mac cần máy ảo có USB passthrough khi agent phải thấy cổng serial.

## Kiến thức cần trước

Bạn dùng được terminal Ubuntu: `ssh`, `sudo`, `systemctl`. Bài cài Jazzy trên laptop (09-01) có thể làm song song. Bài này là máy tính **trên xe**, không phải lần cài đầu trên laptop. ESP32 của chương 02 đã từng xuất hiện một lần thành `/dev/ttyUSB0` hoặc `/dev/ttyACM0` trên máy bạn. Chưa cần Nav2.

## Vì sao bài này nằm trên lộ trình

`rclpy` và `rclcpp` là đường chính của khóa. Chúng chạy trên Ubuntu 24.04 vì gói Jazzy được build cho bản đó. Laptop để học lệnh. Pi 5 hoặc Orin Nano để robot không phải kéo theo laptop khi bạn đã tin cây TF. Tên `/dev/ttyUSB0` đổi mỗi lần cắm thêm một converter. Agent ghi cứng tên đó sẽ im vào buổi demo. `rclgo` là đường đọc thêm cho người đã viết Go. Nó không thay các bài `rclpy` / `rclcpp`, và không có mặt trong checklist chương này.

## Khái niệm

**Raspberry Pi 5.** Ảnh khóa này cần là Ubuntu 24.04 LTS (Noble), bản 64-bit, không phải Ubuntu mới hơn nếu trang tải đang chào 26.04. Jazzy gắn với 24.04. Ảnh Raspberry Pi OS là Debian. Đừng cài `ros-jazzy-*` lên đó rồi chữa lỗi dependency cả tuần. Cách flash ít việc nhất là Raspberry Pi Imager, chọn Ubuntu Server 24.04 cho Pi 5, bật SSH, đặt user. Hướng dẫn nằm ở [Ubuntu trên Raspberry Pi](https://ubuntu.com/tutorials/how-to-install-ubuntu-on-your-raspberry-pi) và trang [tải ảnh](https://ubuntu.com/download/raspberry-pi). Danh sách file 24.04 còn ở [cdimage 24.04](https://cdimage.ubuntu.com/ubuntu/releases/24.04/release/). Trong Imager, nếu mặc định đã nhảy sang 26.04, hãy chọn lại 24.04. Bài Jazzy trên Pi của ROS: [Installing on Raspberry Pi](https://docs.ros.org/en/jazzy/How-To-Guides/Installing-on-Raspberry-Pi.html).

Headless nghĩa là không màn hình. Lần đầu cùng mạng LAN với laptop:

```bash
ssh ubuntu@<địa-chỉ-ip>
```

Tên `.local` chỉ hiện nếu mDNS chạy. Không hiện thì xem bảng DHCP của router. Đừng đoán `raspberrypi.local` trên ảnh Ubuntu. User là user bạn đã gõ trong Imager.

**Jetson Orin Nano.** Hai đời phần mềm không cùng một câu cài ROS.

- JetPack 6.2 dùng rootfs Ubuntu 22.04. Trên máy đó `lsb_release -sc` in `jammy`. Đường apt của khóa này (`ros-jazzy-*`) không phải đường của Jammy. Humble mới là distro apt khớp 22.04. Đừng trộn.
- JetPack 7.2 trên Orin Nano dùng Ubuntu 24.04. Nhân viên NVIDIA trên diễn đàn phát triển, tháng 9 năm 2026, xác nhận Jazzy là distro ROS khớp JetPack 7.2.1. Kiểm tra bài đó khi bạn flash, vì số bản vá còn chạy: [Jazzy với JetPack 7.2.1](https://forums.developer.nvidia.com/t/is-ros2-jazzy-the-correct-version-to-use-with-jetpack-7-2-1-ubuntu-24-04/382439).

Việc bắt buộc trước mọi `apt install ros-`:

```bash
lsb_release -a
```

`noble` thì đi tiếp Jazzy. `jammy` thì dừng, ghi vào sổ, và hoặc ở lại Humble trên board đó hoặc flash JetPack 7 theo [quick start Orin Nano](https://docs.nvidia.com/jetson/orin-nano-devkit/user-guide/latest/quick_start.html) và [cài JetPack](https://docs.nvidia.com/jetson/jetpack/install-setup/index.html). Docker của [dusty-nv/jetson-containers](https://github.com/dusty-nv/jetson-containers) là đường khác khi bạn cần CUDA. Không phải bài bắt buộc tuần này.

**udev.** ESP32 cổng CH340 thường là `1a86:7523`. CP2102 thường là `10c4:ea60`. Đọc máy bạn, đừng chép ví dụ nếu `udevadm` nói khác:

```bash
udevadm info -a -n /dev/ttyUSB0 | grep -E 'idVendor|idProduct' | head
```

File `/etc/udev/rules.d/99-esp32.rules` (đổi vendor/product cho đúng):

```text
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", SYMLINK+="esp32", GROUP="dialout", MODE="0660"
```

Rồi:

```bash
sudo usermod -aG dialout "$USER"
sudo udevadm control --reload-rules
sudo udevadm trigger
ls -l /dev/esp32
```

Đăng xuất SSH và vào lại thì nhóm `dialout` mới có hiệu lực. `/dev/esp32` phải là một symlink. `chmod 777` như một số README lidar là rộng hơn mức khóa này dùng.

**systemd và agent.** Agent micro-ROS nói serial với firmware và nói DDS với laptop. Binary là `micro_ros_agent` trong [micro-ROS-Agent](https://github.com/micro-ROS/micro-ROS-Agent). Trên máy đã có Jazzy, thử `apt-cache search ros-jazzy-micro-ros-agent`. Có gói thì cài gói. Không có thì build theo README của repo đó, rồi sửa `ExecStart` cho đúng đường dẫn bạn vừa cài. Unit `/etc/systemd/system/microros-agent.service`:

```ini
[Unit]
Description=micro-ROS agent on /dev/esp32
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=ubuntu
Environment=ROS_DOMAIN_ID=42
ExecStart=/bin/bash -lc 'source /opt/ros/jazzy/setup.bash && ros2 run micro_ros_agent micro_ros_agent serial --dev /dev/esp32 -b 115200'
Restart=on-failure
RestartSec=2

[Install]
WantedBy=multi-user.target
```

`User=` phải là user đã ở trong nhóm `dialout`. Baud 115200 phải trùng firmware. Nếu agent bạn build không nằm trong overlay mà `ros2 run` thấy, gọi thẳng binary trong `ExecStart` thay vì `ros2 run`.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now microros-agent.service
systemctl status microros-agent.service --no-pager
```

**Mạng và domain.** [Tài liệu domain ID của Jazzy](https://docs.ros.org/en/jazzy/Concepts/Intermediate/About-Domain-ID.html) là chỗ đọc khoảng số hợp lệ hôm bạn cài. Khóa này dùng một số khác 0 khi phòng lab có nhiều người, ví dụ 42, giống hệt nhau trên laptop và SBC:

```bash
grep -q ROS_DOMAIN_ID ~/.bashrc || echo 'export ROS_DOMAIN_ID=42' >> ~/.bashrc
```

Cùng subnet, multicast không bị AP chặn (một số Wi-Fi khách cô lập client). Hai shell khác domain sẽ có hai đồ thị không thấy nhau. `ros2 topic list` rỗng lúc đó là triệu chứng mạng, không phải cài hỏng.

**Docker trên robot.** Ảnh chính thức nằm ở [hub.docker.com/_/ros](https://hub.docker.com/_/ros). Chọn tag Jazzy mà trang đó đang liệt kê hôm bạn kéo, rồi mới `docker pull`. Cài Docker theo [tài liệu Docker cho Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Muốn container thấy DDS của host và thấy serial:

```bash
docker run --rm -it --network host --device /dev/esp32 \
  -e ROS_DOMAIN_ID=42 \
  ros:jazzy
```

Đổi `ros:jazzy` nếu tag trên Hub mang hậu tố khác và bạn đã đọc tên đó trên trang. `--network host` trên Linux chia sẻ stack mạng để discovery không phải NAT. Tài liệu ROS về hai node trong Docker: [Run 2 nodes](https://docs.ros.org/en/jazzy/How-To-Guides/Run-2-nodes-in-single-or-separate-docker-containers.html).

**Mac.** Docker Desktop trên macOS không đưa `/dev/ttyUSB0` của Linux vào container. Đường làm bài có ESP32 là một máy ảo Ubuntu 24.04 (UTM, VMware hoặc Parallels) với USB passthrough, rồi cài Jazzy trong máy ảo như bài 09-01. Docker trên Mac vẫn hợp để chạy `ros2` CLI không đụng phần cứng. Gazebo có giao diện trong Docker trên Mac là một dự án khác. Đừng chặn chương 09 vì host là macOS. Chặn khi bạn cần serial mà chỉ có Docker Desktop.

`rclgo`: repo [tiiuae/rclgo](https://github.com/tiiuae/rclgo) là binding Go. Đọc sau khi một talker `rclpy` đã chạy. Không đổi checklist.

## Lab

### An toàn

SBC trên xe chưa được nối VM motor trong bài này. Nguồn 5 V của Pi hoặc nguồn Jetson theo đúng giắc của hãng. Không cấp 5 V đó từ cực pin 2S.

### Các bước

1. Ghi host bạn sẽ dùng cho Jazzy: laptop, Pi 5, hay Jetson. Dán `lsb_release -sc` nếu máy đã có. `noble` được đi tiếp. `jammy` trên Jetson được ghi rõ và không cài Jazzy.
2. Nếu có Pi 5: flash Ubuntu Server 24.04, SSH vào, lưu địa chỉ IP vào sổ.
3. Cắm ESP32, tạo rule udev, dán `ls -l /dev/esp32`.
4. Viết unit systemd. `systemctl status` phải là active, hoặc sổ ghi lỗi thiếu binary và câu bạn sẽ build agent từ repo micro-ROS. Một unit sai đường dẫn mà bạn đã đọc log là đạt của bước giấy. Một unit bạn chưa bao giờ `start` là chưa đạt.
5. Đặt `ROS_DOMAIN_ID` trên hai máy. Từ laptop, sau khi source Jazzy, `ros2 topic list` phải thấy topic của agent **hoặc** bạn ghi là agent chưa có client (danh sách không có topic micro-ROS, nhưng `ROS_DOMAIN_ID` in ra giống nhau ở hai đầu).

### Kết quả mong đợi

`lab-notes.md` có: bản Ubuntu, IP, symlink `/dev/esp32` hoặc lý do chưa có board, trạng thái systemd, và hai dòng `ROS_DOMAIN_ID`.

### Lỗi thường gặp

| Bạn thấy | Cần kiểm |
| --- | --- |
| `ros2` không thấy node trên SBC | Domain khác nhau, khác subnet, hoặc Wi-Fi cô lập client |
| `/dev/esp32` mất sau khi rút cắm | Rule không khớp vendor. Chạy lại `udevadm info` |
| Agent restart liên tục | Sai baud, sai user (không thuộc `dialout`), hoặc binary không có trong `PATH` của unit |
| `apt install ros-jazzy-desktop` lỗi trên Jetson | `jammy`. Dừng |
| Docker trên Mac không thấy USB | Đúng giới hạn. Chuyển agent sang máy ảo hoặc sang Pi |
| Pi Imager ghi Ubuntu 26.04 | Jazzy không phải target của ảnh đó. Ghi lại 24.04 |

## Bài tập

1. Vì sao rule udev dùng `SYMLINK` thay vì một script `chmod` mỗi lần boot?
2. Unit để `User=root` cho nhanh. Bạn mất nhóm nào, và rủi ro nào thêm?
3. Laptop domain 42, Pi domain 7, cùng Wi-Fi. `ros2 topic list` trên laptop trống. Sửa một biến nào?
4. Ảnh Ubuntu trên Pi là 26.04. Bạn còn được làm bài 09-01 nguyên văn không?
5. `rclgo` giải quyết giúp bước nào trong lab này, và bước nào thì không?

### Gợi ý đáp án

1. Tên ổn định theo vendor/product, quyền theo nhóm `dialout`, không cần nhớ lệnh sau mỗi lần cắm. 2. Root bỏ qua `dialout` theo kiểu xấu và biến mọi lỗi agent thành tiến trình root. Giữ user thường trong `dialout`. 3. Đưa cả hai về cùng một số. 4. Không. Bài 09-01 là Jazzy trên 24.04. Ghi lại thẻ, hoặc chấp nhận rằng bạn đang ngoài lộ trình apt. 5. Không giúp udev, systemd, hay domain. Nó chỉ là một cách viết node sau khi DDS đã sống. Lộ trình chính vẫn là `rclpy` hoặc `rclcpp`.
